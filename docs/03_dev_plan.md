# 投票系統 — 開發計劃

> 版本：v1.1 | 日期：2026-09-04
> 配套文件：01_requirements.md（佛光山幹部改選投票系統需求 v1.1）、02_architecture.md（v1.1）

> **v1.1 變更摘要**：① 新增分區（divisions）模組與五區數據模型，M1 schema 增加 divisions 表、candidates/members/votes/appointments 增加 division_id；② M2 身份確認改為「姓名 + 卡號」雙欄位 + 簡繁歸一化 + 分區路由；③ M3 新增會員 Excel/CSV 匯入（簡繁雙存）、分區管理頁面、分區級計票；④ 加賽（平票再投）由「預留」提升為**明確開發項**（分區級加賽）；⑤ 工期由 10 天上調至 **12 個工作日**（新增分區、匯入、簡繁、加賽工作量）。

### 環境實際配置（no-root，非 Docker）

> 原計劃用 Docker Compose（1.9），實際環境無 Docker，改用 **deb 提取 + 本地啟動**，效果等同。

| 組件 | 版本 | 部署方式 | 端口 |
|------|------|----------|------|
| PostgreSQL | 18.6 | `apt-get download` + `dpkg-deb -x` 提取到 `~/.local/pgsql/`，`initdb` 初始化 data 目錄 | 5432 |
| Redis | 8.0.5 | `apt-get download` + `dpkg-deb -x` 提取到 `~/.local/redis/` | 6379 |
| FastAPI | 0.141.1 | `python3 -m venv` + `get-pip.py`（無 ensurepip）+ pip 裝 17 依賴 | 8000 |

**啟動腳本**：
- `scripts/start_all.sh [start|stop|status]` — 一鍵啟停 PG + Redis + API
- `scripts/pgctl.sh` / `scripts/redisctl.sh` — 單獨管控 PG / Redis

**資料庫**：`fgs_vote`（UTF8），應用用戶 `fgs_app`（權限已授予 public schema）。

**初始數據**：管理員 `admin`（首次登入強制改密）+ 五區（東/南/西/北/中）。

**M2 驗收**：
- 輸入姓名 + 卡號 → 簡繁匹配 → 顯示分區 + 投票人資訊 → 選 2 名本區候選人 → 提交 → 「投票成功」
- 簡體姓名輸入能正確匹配（繁體存檔）
- 5 個分區各 1 手機投票，結果頁面 2s 內全部更新（分區級）
- 同一卡號第二次訪問提示「您已投過票，無需重複投票」
- 姓名與卡號不匹配時報錯（400）
- 跨區候選人提交被拒（403）
- 投票視窗外無法投票（未開始/已結束有對應提示）
- 超出 max 票數時禁止勾選
- PG 宕機時投票不丟（Redis Stream 緩衝）

**M4 驗收**（對齊需求 9.1-9.5）：
- 壓測透過：100 併發投票（跨五區）P99 < 200ms，150 QPS 查詢 P99 < 50ms
- 降級測試透過：PG/Redis 任一故障，系統不中斷、投票不丟
- 安全測試透過：無注入/越權/洩露；同一卡號不可重複投票；**跨區提交被拒**；代投可追溯；投票記錄不可修改/刪除
- 完整選舉演練成功（**五區 + 加賽 + 第二輪 + 幹部指派 + 匯出**）
- 生產環境可訪問，HTTPS 正常
- 備份 + 恢復測試透過

## 4. 依賴與風險

### 4.1 外部依賴

| 依賴 | 說明 | 風險 | 緩解 |
|------|------|------|------|
| 域名 + 證書 | HTTPS | 需要域名 + ICP 備案（國內雲） | 提前準備；Let's Encrypt 免費證書 |
| 伺服器 | 4C8G 雲伺服器 | 採購/配置 | 提前購買 |
| 會員名單 | 後臺匯入 Excel/CSV（卡號、姓名、所屬分區） | 名單不準確/遺漏/分區錯 | 投票前由會務組核對；匯入前可修改；匯入報告逐行校驗 |

> **零外部服務依賴**：身份確認只用「姓名 + 佛光會員卡號」（後臺匯入），不用簡訊、不用微信 OAuth。簡繁轉換用開源 OpenCC（純 Python）。省掉外部服務認證、金鑰管理和額外成本。

### 4.2 技術風險

| 風險 | 機率 | 影響 | 緩解 |
|------|------|------|------|
| 微信內建瀏覽器相容問題 | 中 | 投票頁面顯示異常 | Day 6 開始真機測試（iOS + Android）；Tailwind 相容性 |
| 現場 Wi-Fi 不穩定 | 中 | 投票提交失敗 | 前端重試 + 後端冪等；4G 熱點備用 |
| 平票處理 | 中 | 某區選舉結果不明確 | 分區級加賽（已納入 M3 開發）；投票前管理員確定規則；系統確認計票時偵測平票並提示 |
| 簡繁匹配誤差 | 低 | 姓名匹配失敗/錯誤匹配 | OpenCC 標準映射 + 異體字表（核/峯）；單元測試覆蓋；匹配失敗明確報錯不誤放 |
| 開放問題未確認 | 中 | 需求變動返工 | 加賽細節、每區票數、第二輪名單、部署環境等（需求第 10 章）應在 Day 1-2 前確認 |

|------|------|

```python
# loadtest.py
from locust import HttpUser, task, between

class Voter(HttpUser):
    wait_time = between(1, 3)

    @task
    def view_results(self):
        # 分區級查詢（round_id + division_id）
        self.client.get("/api/votes/results?round_id=1&division_id=1")

class VoteSubmitter(HttpUser):
    wait_time = between(10, 30)

    @task
    def submit_vote(self):
        # 模擬投票提交（跨五區分散）
        self.client.post("/api/votes/submit", json={
            "voter_token": "test_token",
            "round_id": 1,
            "candidate_ids": [1, 2]
        })
```

- 100 併發提交（峰值 30% 同時投，跨五區）→ P99 < 200ms
- 持續 10 分鐘，無錯誤
