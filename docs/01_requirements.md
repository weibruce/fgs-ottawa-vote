# 佛光山幹部改選投票系統 — 需求文件

> 版本：v1.0 | 日期：2026-09-03 | 狀態：待評審

---

## 1. 專案背景

某組織年度選舉大會，現場約 300 人參與投票。選舉流程分兩輪：

- **第一輪**：全體會員投票選舉會長（從 5-7 名候選人中選 1 人，每人可投 1-2 票）
- **第二輪**：由第一輪當選的會長 + 會務幹部（小範圍）票選出副會長 1 人
- **幹部指派**：由會長指派（祕書、財務、總務等會務幹部），不走投票

---

## 2. 角色定義

| 角色 | 說明 | 許可權 |
|------|------|--------|
| 普通投票人 | 透過微信掃碼或投票連結，線上投票 | 投票、檢覘實時結果 |
| 後臺管理員 | 會務組工作人員（1-2 人） | 配置候選人、開啟/關閉投票、檢覘計票、匯出資料 |

---

## 3. 功能需求

### 3.1 投票頁面（移動端優先）

#### 3.1.1 進入方式

- **微信掃碼**：掃描二維碼 → 進入用戶身份確認頁
- **投票連結**：點選連結進入 → 直接進入用戶身份確認頁

兩種路徑最終都匯聚到 **用戶身份確認頁**。

#### 3.1.2 身份確認驗證

使用者輸入：**佛光會員號**（必填）

- 系統依會員號查會員名單（後臺匯入），自動帶出會員姓名
- 頁面顯示「請確認：張三（佛光卡 FG20260001）」，本人或受委託者點選「確認」後進入投票
- 若該會員號已投過票，直接提示「您已投過票，無需重複投票」，不再允許投票
- 允許代投：來不了本人可委託他人持會員號代投，系統不區分本人/代投
- 不使用手機號、簡訊驗證碼（零外部依賴、零成本）

#### 3.1.3 候選人展示

展示 5-7 名候選人，每人包含：

- 姓名
- 頭像（可選，後臺上傳）
- 職位/部門（一行簡介）
- 候選人介紹（可選，最多 200 字）
- 競選宣言（可選，最多 200 字）

候選人按後臺配置的順序展示（或隨機排序，可配置）。

#### 3.1.4 投票操作

- 每輪投票每人可投 1-2 票（具體票數由後臺配置，第一輪預設 2 票，可調整）
- 候選人列表為多選 checkbox
- 已選數量實時顯示（如「已選 1/2 票」）
- 超過上限時禁止繼續勾選，給出提示
- 最少投 1 票（允許棄部分票，但必須至少投 1 票，可配置）
- 點選「確認投票」按鈕
- 提交前二次確認彈窗：「確認將票投給 甲、乙？提交後不可修改。」
- 提交後顯示「投票成功」頁面，可點擊「進入投票展示頁面」按鈕
- 實時展示頁面可查看實時投票結果

#### 3.1.5 投票視窗

後臺可設定投票開始/結束時間：

| 狀態 | 行為 |
|------|------|
| 未開始 | 頁面顯示「投票尚未開始，開始時間 XX:XX」 |
| 進行中 | 正常投票 |
| 已結束 | 頁面顯示「投票已結束」，不再接受新票，但可檢覘最終結果 |

---

### 3.2 實時結果展示

#### 3.2.1 展示內容

- 每位候選人的當前得票數（柱狀圖 + 數字）
- 總投票人數 / 已投票人數
- 投票進度條
- 最高票候選人高亮

#### 3.2.2 更新方式

- 前端輪詢，間隔 2 秒，更新投票統計（可配置 1-10 秒）
- 每次輪詢呼叫 `GET /api/votes/results?round=1`
- 資料從 Redis 快取讀取（非資料庫）
- 頁面自動重新整理，無需手動操作

#### 3.2.3 展示時機

- **投票進行中**：實時展示（每 2s 更新）
- **投票結束後**：展示最終結果，停止輪詢

---

### 3.3 後臺管理系統

#### 3.3.1 登入

- 管理員帳號 + 密碼登入（session 或 JWT）
- 初始帳號由系統初始化時建立（admin / 初始密碼，首次登入強制修改）

#### 3.3.2 候選人管理

- 新增候選人：姓名、頭像、職位、介紹、競選宣言、排序
- 編輯候選人
- 刪除候選人（投票開始前可刪除，開始後鎖定）
- 批次匯入（Excel 可選）

#### 3.3.3 投票配置

| 配置項 | 說明 | 預設值 |
|--------|------|--------|
| 投票輪次 | 當前第幾輪（1=會長選舉，2=副會長選舉） | 1 |
| 每人票數 | 每人可投幾票 | 2 |
| 最少票數 | 最少需投幾票 | 1 |
| 匿名投票 | 是否開啓匿名投票 | 開啓 |
| 投票開始時間 | 日期時間 | - |
| 投票結束時間 | 日期時間 | - |
| 候選人排序 | 固定順序 / 隨機 | 固定 |
| 投票狀態 | 未開始 / 進行中 / 已結束 | 未開始 |

- **開啟投票**：設定狀態為「進行中」，生成/啟用投票連結
- **關閉投票**：設定狀態為「已結束」，停止接受新票
- **生成投票二維碼**：基於投票連結生成，現場張貼/展示

#### 3.3.4 實時計票

與投票頁面相同的實時結果展示，額外顯示：

- 投票人明細（姓名、會員號、投票時間、投了誰），開啓匿名投票後不顯示
- 按時間線展示投票進度
- 支援暫停/恢復輪詢

#### 3.3.5 輪次管理

**第一輪結束**：管理員手動點選「確認第一輪計票完成」

- 系統鎖定第一輪所有資料
- 顯示第一輪結果（最高票者當選會長）
- 後臺解鎖「配置第二輪」功能

**配置第二輪**：

- 設定第二輪候選人（會務幹部名單，由會長指定，通常 3-5 人）
- 設定第二輪投票人白名單（指定會員號名單：會長 + 會務幹部）
- 設定第二輪每人票數（通常 1 票）
- 設定第二輪投票連結（獨立連結，僅白名單會員號可訪問）
- 開啟第二輪投票

**第二輪結束**：管理員手動點選「確認第二輪計票完成」

- 系統鎖定第二輪資料
- 顯示副會長當選者
- 開啟幹部任命

**幹部指派開始**：

- 待會長指派，祕書、財務、總務等會務幹部
- 管理員在各個職務名稱下，手動輸入會務幹部姓名和任期

**幹部指派結束**：管理員手動點選「確認幹部指派完成」

- 系統鎖定幹部指派資料
- 顯示會務幹部職位、姓名和任期

#### 3.3.6 資料匯出

- 匯出第一輪投票明細（CSV/Excel）：姓名、會員號、投票時間、投了誰（開啓匿名投票後不顯示）
- 匯出第二輪投票明細
- 匯出幹部指派明細
- 匯出彙總統計
- 匯出/維護會員名單（匯入 Excel：會員號、姓名；投票前完成）

#### 3.3.7 系統設定

- 修改管理員密碼
- 配置輪詢間隔
- 配置投票視窗預設時間

## 4. 非功能需求

### 4.1 效能

| 指標 | 要求 |
|------|------|
| 投票請求響應時間 | < 200ms（P99） |
| 結果查詢響應時間 | < 50ms（P99，Redis 快取） |
| 實時性 | 投票後 2-5 秒內結果頁面可見更新 |
| 併發 | 支援 100 人同時提交投票（300 人現場，峰值約 30% 同時投） |
| 可用性 | 投票視窗內零停機（資料庫掛了投票不丟） |

### 4.2 安全

| 項 | 要求 |
|----|------|
| 傳輸 | 全站 HTTPS |
| 防重投票 | 佛光會員號唯一（round + member_id 唯一約束）+ voter_token 機制 |
| 管理員介面 | 獨立鑑權，與投票介面隔離 |
| 資料 | 匿名投票模式下後臺不顯示投票人姓名/會員號；匯出時遵循同一規則 |
| 投票資料 | 不可篡改：投票記錄寫入後只讀（無 UPDATE/DELETE 介面） |

### 4.3 可用性

| 項 | 要求 |
|----|------|
| 投票連結 | 短鏈或可直接記憶的 URL（如 `vote.example.org/r1`） |
| 移動端 | 投票頁面移動端優先，適配 iOS / Android 瀏覽器 + 微信內建瀏覽器 |
| 降級 | 資料庫不可用時，投票寫入 Redis 佇列緩衝，恢復後自動補寫 |
| 監控 | 投票視窗內每 30 秒健康檢查（API、Redis、PG） |

### 4.4 資料量

| 項 | 估算 |
|----|------|
| 投票人 | ~300 人 |
| 投票記錄 | ~300 條（第一輪）+ ~10 條（第二輪） |
| 輪詢請求 | 300 人 × 每 2s 一次 = 150 QPS（結果查詢） |
| 資料量 | < 10MB |

## 5. 業務規則

### 5.1 第一輪（會長選舉）

- 全體 ~300 名會員參與
- 候選人 5-7 人（後臺配置）
- 每人可投 1-2 票（預設 2 票，後臺可配）
- 得票最高者當選會長
- 若出現平票（最高票多人並列）：
  - **規則 A**（預設）：進入加賽，僅平票候選人重新投票
  - **規則 B**（備選）：由會務組抽籤決定
  - 具體規則由管理員在投票前確定，系統需支援加賽輪次（需要討論是否開發）
- 第一輪結束後，後臺鎖定資料，管理員手動觸發第二輪

### 5.2 第二輪（副會長選舉）

- 參與者：第一輪當選的會長 + 會務幹部（小範圍，通常 3-5 人）
- 候選人：會長指定的副會長候選人（後臺配置，通常 2-4 人）
- 每人投 1 票
- 得票最高者當選副會長
- 平票處理同第一輪
- 第二輪結束後，後臺鎖定資料

### 5.3 幹部指派

- 祕書、財務、總務等崗位由會長指派
- 不走投票系統，系統僅記錄任命結果（後臺手動錄入）
- 後臺記錄幹部任命資訊（姓名、崗位、任期）

### 5.4 任期

- 會長任期 2 年一任
- 建議承擔 2 任（最多 4 年）
- 系統在候選人資訊中顯示「當前已任屆數」，後臺可配置

## 6. 投票流程（端到端）

### 第一輪：會長選舉

```
[管理員] 配置候選人（5-7 人）
    ↓
[管理員] 配置投票參數（票數、時間視窗）
    ↓
[管理員] 生成投票連結 + 二維碼，可供現場展示
    ↓
[投票人] 微信掃碼 / 輸入線上投票地址
    ↓
[投票人] 輸入佛光會員號
    ↓
[系統] 查會員名單帶出姓名，展示確認頁；檢查該會員號是否已投票（Redis + PG）
    ↓
[投票人] 選擇 1-2 名候選人 → 確認投票
    ↓
[系統] 校驗（未投票、票數合法、在投票視窗內）
    ↓
[系統] 寫入投票記錄（PG）+ 更新 Redis 計數
    ↓
[系統] 返回「投票成功」
    ↓
[所有投票人 + 後臺] 每 2s 輪詢結果，看到票數變化
    ↓
[管理員] 投票結束，確認計票完成
    ↓
[系統] 鎖定第一輪，顯示結果（最高票 = 會長）
```

### 第二輪：副會長選舉

```
[管理員] 配置第二輪候選人（副會長候選人 2-4 人）
    ↓
[管理員] 配置第二輪參數（1 票、投票人 = 會長 + 幹部）
    ↓
[管理員] 生成第二輪投票連結（獨立連結）
    ↓
[會長 + 幹部] 通過第二輪連結投票
    ↓
[管理員] 投票結束，確認計票完成
    ↓
[系統] 鎖定第二輪，顯示結果（最高票 = 副會長）
```

### 幹部指派

```
[會長] 指派祕書、財務、總務等
    ↓
[管理員] 後臺手動錄入任命資訊
    ↓
[系統] 展示完整選舉結果（會長 + 副會長 + 幹部名單）
```

## 7. 邊界情況

| 場景 | 處理 |
|------|------|
| 輸入的會員號不在名單中 | 提示「未找到該會員號，請核實」，不進入投票 |
| 投票視窗內資料庫宕機 | 投票寫入 Redis 佇列（LPUSH），消費者恢復後批次寫 PG；前端提示「投票已提交，正在處理」 |
| 投票視窗內 Redis 宕機 | 降級為直接寫 PG（效能下降但可用）；防重檢查降級為 PG 查詢 |
| 同一會員號先掃碼後直接 URL | 會員號唯一，第二次用同一會員號時檢測到已投票，顯示「您已投過票」 |
| 投票視窗結束後還有人提交 | 返回「投票已結束」，不寫入 |
| 平票（最高票多人並列） | 進入加賽輪次（僅平票候選人重新投票），或按後臺配置的處理規則（需要討論是否開發） |
| 管理員誤操作刪除候選人（投票已開始） | 投票開始後候選人列表鎖定，不允許刪除/修改 |
| 投票人投了 0 票（全部不選） | 若配置最少票數為 1，前端禁止提交；若配置最少 0 票，允許提交空票（視為棄票） |
| 網路中斷後重試 | 前端提交後顯示「正在提交...」，超時後允許重試；後端冪等（同一 token + 同一輪次只接受一次） |
| 第二輪投票人非指定人員 | 第二輪連結有訪問控制（僅指定會員號可投票），非指定會員號提示「您無許可權參與本輪投票」 |

## 8. 資料字典

### 8.1 核心實體

| 實體 | 欄位 | 說明 |
|------|------|------|
| **member**（會員） | id, member_no, name, created_at | 會員名單（後臺匯入，member_no 唯一） |
| **candidate**（候選人） | id, name, avatar_url, position, description, slogan, sort_order, term_count | 候選人資訊 |
| **round**（投票輪次） | id, title, status, min_votes, max_votes, anonymous, allowed_member_nos, start_time, end_time, candidate_ids, created_at | 輪次配置（allowed_member_nos：第二輪白名單，null=不限） |
| **vote**（投票記錄） | id, round_id, member_id, candidate_ids[], voted_at, status | 投票記錄（不可修改，round+member_id 唯一） |
| **vote_result**（計票結果） | round_id, candidate_id, vote_count, updated_at | 快取層，Redis 為主，PG 備份 |
| **admin**（管理員） | id, username, password_hash, created_at | 管理員 |
| **appointment**（幹部任命） | id, name, position, appointed_by, appointed_at, term | 幹部任命記錄 |

### 8.2 狀態機

```
round.status:
  draft → active → closed → locked
  （草稿）  （進行中）  （已結束）  （已鎖定，不可再修改）

member 狀態（per round）:
  not_voted → voted
  （未投票）  （已投票）
```
