# 佛光山幹部改選投票系統 — 需求文件

> 版本：v1.1 | 日期：2026-09-04 | 狀態：待評審

> **v1.1 變更摘要**：① 第一輪改為**五分區（東/南/西/北/中）**各自獨立選舉，各區候選人、會長、副會長、各職幹部均不同；② 投票入口統一（同一連結 + 二維碼），依會員所屬分區自動路由到對應分區投票頁；③ 身份確認改為「姓名 + 佛光會員卡號」雙欄位校驗 + 顯示所屬分區；④ 新增**代理投票**（checkbox 標記）；⑤ 新增**平票再投**（細節待定，先佔位）；⑥ 會員名單支援 Excel/CSV 匯入，姓名儲存簡繁兩種形式以支援簡體輸入匹配。

---

## 1. 專案背景

某組織年度選舉大會，現場約 300 人參與投票。選舉分兩輪，**第一輪採五分區制**：

- **第一輪（分區選舉）**：會員按**所屬分區**（東、南、西、北、中，共 5 區）各自投票，**每區獨立選出本區的會長、副會長**；祕書、財務、總務等分區幹部由本區當選會長指派（或按分區規則產生），**各分區的候選人、當選結果、幹部均不相同**。
- **第二輪**：由第一輪當選的各區會長 + 會務幹部（小範圍）票選出總會副會長 1 人（視實際組織架構調整，待確認）。
- **幹部指派**：由各區會長指派本區會務幹部（祕書、財務、總務等），不走投票，後台手動錄入。

> 說明：五個分區在第一輪是**並行的獨立選舉**，共享同一套系統、同一個投票入口，但候選人列表、投票人範圍、計票結果彼此隔離。

---

## 2. 角色定義

| 角色 | 說明 | 許可權 |
|------|------|--------|
| 普通投票人 | 透過微信掃碼或投票連結，線上投票 | 身份確認、本分區投票、檢視本分區實時結果 |
| 分區管理員 | 各分區負責人（可選，5 區各 1 人） | 檢視本分區計票結果（如需分區級管理） |
| 後臺管理員 | 會務組工作人員（1-2 人） | 配置分區/候選人/會員名單、開啟/關閉投票、檢視計票、匯出資料 |

## 3. 功能需求

### 3.1 投票頁面（移動端優先）

#### 3.1.1 進入方式（統一入口）

- **微信掃碼**：掃描二維碼 → 進入身份確認頁
- **投票連結**：點選連結進入 → 進入身份確認頁

> **入口統一**：五個分區共用**同一個投票連結 + 同一張二維碼**。會員進入後系統依「姓名 + 佛光會員卡號」判定其**所屬分區**，自動路由到該分區的投票頁面。不同分區的會員看到不同的候選人列表，但入口完全相同。

#### 3.1.2 身份確認

使用者輸入以下欄位：

| 欄位 | 必填 | 說明 |
|------|------|------|
| 姓名 | 是 | 會員姓名（支援簡體或繁體輸入，系統自動匹配） |
| 佛光會員卡號 | 是 | 唯一識別碼，後台匯入 |
| 是否由他人代理投票 | 否（checkbox） | 勾選表示代他人投票（見 3.1.6） |

**校驗邏輯**（點選「確認」後）：

1. 依「佛光會員卡號 + 姓名」查會員名單（後台匯入）
   - 卡號不存在 → 報錯「未找到該會員卡號，請核實」
   - 卡號存在但姓名不匹配 → 報錯「姓名與會員卡號不匹配，請核實」
   - 卡號與姓名匹配 → 通過
2. 匹配成功後，頁面**顯示當前投票人資訊**：
   - 姓名
   - 佛光會員卡號
   - 所屬分區（東/南/西/北/中）
   - 是否由他人代理投票（是/否）
3. 檢查該會員是否已在本分區投過票
   - 已投 → 顯示「您已投過票，無需重複投票」，不顯示「開始投票」按鈕
   - 未投 → 顯示「開始投票」按鈕
4. 點選「開始投票」→ 進入該分區的候選人選擇頁

> 姓名匹配採用**簡繁雙存 + 歸一化比較**策略（見 3.3.8），現場有人輸入簡體姓名也能匹配到繁體存檔。

#### 3.1.3 分區投票頁面

- 進入後展示**當前分區**的候選人列表（僅該區候選人，其他區不顯示）
- 頁面頂部顯示「XX 區會長/副會長選舉」標識 + 投票人姓名/卡號/分區
- 每位候選人包含：姓名、頭像（可選）、職位/部門、候選人介紹（可選，≤200 字）、競選宣言（可選，≤200 字）
- 候選人按後台配置順序展示（或隨機，可配置）

#### 3.1.4 投票操作

- 每分區投票每人可投 1-2 票（具體票數由後台按分區配置，預設 2 票）
- 候選人列表為多選 checkbox
- 已選數量實時顯示（如「已選 1/2 票」）
- 超過上限時禁止繼續勾選，給出提示
- 最少投 1 票（可配置）
- 點選「確認投票」按鈕
- 提交前二次確認彈窗：「確認將票投給 甲、乙？提交後不可修改。」
- 提交後顯示「投票成功」頁面，可點擊「進入投票展示頁面」按鈕
- 實時展示頁面可查看**本分區**實時投票結果

#### 3.1.5 投票視窗

後台可設定投票開始/結束時間（五區統一視窗，或各區可獨立設定，預設統一）：

| 狀態 | 行為 |
|------|------|
| 未開始 | 頁面顯示「投票尚未開始，開始時間 XX:XX」 |
| 進行中 | 正常投票 |
| 已結束 | 頁面顯示「投票已結束」，不再接受新票，但可檢視最終結果 |

#### 3.1.6 代理投票

- 身份確認頁提供 checkbox「**是否由他人代理投票**」
- 本人來不了現場、或本人不熟線上操作時，可由他人代為投票
- 勾選後，系統在該票記錄上標記 `proxy = true`（可選填代投人姓名，待確認）
- 系統**不阻擋**代投（接受代投場景），僅做**標記 + 可追溯**
- 後台投票人明細中可看到哪些票是代理投票，公示/爭議時可追溯
- 代理投票同樣受「同一會員卡號本分區只能投一次」約束

> 設計取捨：本方案以 checkbox 標記代投（用戶提議的方案）。系統防「重複投票」，不防「首次即代投」（即不驗證投票人是否本人）。若需更強約束（如代投需出示委託書/代投人身份），留待後續討論。

---

### 3.2 實時結果展示（分區級）

#### 3.2.1 展示內容

- **投票人側**：展示**當前分區**的實時結果
  - 該區每位候選人的當前得票數（柱狀圖 + 數字）
  - 該區總投票人數 / 已投票人數
  - 投票進度條
  - 最高票候選人高亮
- **後台側**：可切換查看各分區結果，或總覽五區彙總

#### 3.2.2 更新方式

- 前端輪詢，間隔 2 秒（可配置 1-10 秒）
- 每次輪詢呼叫 `GET /api/votes/results?round=1&division=東`
- 資料從 Redis 快取讀取（非資料庫）
- 頁面自動重新整理，無需手動操作

#### 3.2.3 展示時機

- **投票進行中**：實時展示（每 2s 更新）
- **投票結束後**：展示最終結果，停止輪詢

### 3.3 後臺管理系統

#### 3.3.1 登入

- 管理員帳號 + 密碼登入（session 或 JWT）
- 初始帳號由系統初始化時建立（admin / 初始密碼，首次登入強制修改）

#### 3.3.2 分區管理

- 維護五個分區（東、南、西、北、中），每區可配置：
  - 分區名稱、標識色（可選）
  - 該區投票視窗（可獨立於全局，預設跟隨全局）
  - 該區每人票數、最少票數
- 新增/編輯/刪除分區（投票開始前可改，開始後鎖定結構）

#### 3.3.3 候選人管理（按分區）

- 候選人**綁定到特定分區**（每區獨立候選人池）
- 新增候選人：姓名、頭像、職位、介紹、競選宣言、**所屬分區**、排序
- 編輯 / 刪除候選人（投票開始前可改，開始後鎖定）
- 批次匯入（Excel 可選）
- 後台可按分區篩選查看候選人

#### 3.3.4 投票配置

| 配置項 | 說明 | 預設值 |
|--------|------|--------|
| 投票輪次 | 當前第幾輪（1=分區選舉，2=總會副會長選舉） | 1 |
| 每人票數 | 每人可投幾票（可全局或分區級） | 2 |
| 最少票數 | 最少需投幾票 | 1 |
| 匿名投票 | 是否開啓匿名投票 | 開啓 |
| 投票開始時間 | 日期時間 | - |
| 投票結束時間 | 日期時間 | - |
| 候選人排序 | 固定順序 / 隨機 | 固定 |
| 投票狀態 | 未開始 / 進行中 / 已結束 | 未開始 |

- **開啟投票**：設定狀態為「進行中」，啟用統一投票連結
- **關閉投票**：設定狀態為「已結束」，停止接受新票
- **生成投票二維碼**：基於統一投票連結生成，現場張貼/展示（五區共用同一連結/碼）

#### 3.3.5 實時計票（分區級）

與投票頁面相同的實時結果展示，額外顯示：

- 可切換分區（東/南/西/北/中）或總覽彙總
- 該分區投票人明細（姓名、會員卡號、所屬分區、是否代投、投票時間、投了誰），開啓匿名投票後不顯示
- 按時間線展示投票進度
- 支援暫停/恢復輪詢

#### 3.3.6 輪次管理

**第一輪（分區選舉）結束**：管理員手動點選「確認第一輪計票完成」

- 系統鎖定五區所有第一輪資料
- 顯示各分區結果（每區最高票者當選本區會長/副會長）
- 若某區出現平票 → 觸發平票再投流程（見 5.1，細節待討論）
- 後臺解鎖「配置第二輪」功能

**配置第二輪**：

- 設定第二輪候選人（由會長指定的副會長候選人，通常 2-4 人）
- 設定第二輪投票人白名單（指定會員卡號名單：各區會長 + 會務幹部）
- 設定第二輪每人票數（通常 1 票）
- 設定第二輪投票連結（獨立連結，僅白名單卡號可訪問）
- 開啟第二輪投票

**第二輪結束**：管理員手動點選「確認第二輪計票完成」

- 系統鎖定第二輪資料
- 顯示副會長當選者
- 開啟幹部任命

**幹部指派開始**：

- 由**各區當選會長**指派本區祕書、財務、總務等會務幹部
- 管理員在「分區 → 職務」下，手動輸入幹部姓名和任期

**幹部指派結束**：管理員手動點選「確認幹部指派完成」

- 系統鎖定幹部指派資料
- 顯示各分區會務幹部職位、姓名和任期

#### 3.3.7 資料匯出

- 匯出各分區投票明細（CSV/Excel）：姓名、會員卡號、所屬分區、是否代投、投票時間、投了誰（匿名模式下不顯示身份）
- 匯出第二輪投票明細
- 匯出幹部指派明細（按分區）
- 匯出五區彙總統計
- 匯出/維護會員名單（見 3.3.8）

#### 3.3.8 會員名單匯入（Excel/CSV）

- 支援 **Excel（.xlsx）** 或 **CSV** 匯入佛光會員名單
- 匯入欄位：
  - **佛光會員卡號**（必填，**唯一**，重複卡號匯入時報錯並列出衝突行）
  - **姓名**（必填，繁體中文）
  - **所屬分區**（必填：東/南/西/北/中）
  - 手機號（選填，僅備註/通知用，不做驗證）
- **姓名簡繁處理**：
  - 資料庫**同時儲存繁體姓名與簡體姓名**兩欄（`name_trad`、`name_simp`），匯入時由系統用簡繁轉換庫（如 OpenCC）自動由繁體生成簡體，避免手動維護
  - 身份確認時，輸入的姓名先做**簡繁歸一化**再比較，因此現場有人輸簡體也能匹配繁體存檔
  - 備選方案（待確認）：只存一種 + 查詢時即時轉換；本方案採「雙存」以換取查詢簡便與結果頁顯示繁體
- 匯入前預檢：卡號唯一性、分區合法性、必填欄位，預檢失敗不寫入並回報錯誤清單
- 投票前完成匯入；投票開始後鎖定會員名單（可增補需管理員權限，待確認）
- 支援重新匯入（覆蓋或增量，待確認）

#### 3.3.9 平票再投管理（佔位）

- 第一輪某分區出現平票時，後台可啟動該分區的**加賽輪次**
- 細節（加賽範圍、投票人、票數、次數上限）待討論，先佔位
- 見業務規則 5.1

#### 3.3.10 系統設定

- 修改管理員密碼
- 配置輪詢間隔
- 配置投票視窗預設時間

## 4. 非功能需求

### 4.1 效能

| 指標 | 要求 |
|------|------|
| 投票請求響應時間 | < 200ms（P99） |
| 結果查詢響應時間 | < 50ms（P99，Redis 快取） |
| 實時性 | 投票後 2-5 秒內結果頁面可見更新 |
| 併發 | 支援 100 人同時提交投票（300 人現場，峰值約 30% 同時投） |
| 可用性 | 投票視窗內零停機（資料庫掛了投票不丟） |

### 4.2 安全

| 項 | 要求 |
|----|------|
| 傳輸 | 全站 HTTPS |
| 防重投票 | 佛光會員號唯一（round + member_id 唯一約束）+ voter_token 機制 |
| 管理員介面 | 獨立鑑權，與投票介面隔離 |
| 資料 | 匿名投票模式下後臺不顯示投票人姓名/會員號；匯出時遵循同一規則 |
| 投票資料 | 不可篡改：投票記錄寫入後只讀（無 UPDATE/DELETE 介面） |

### 4.3 可用性

| 項 | 要求 |
|----|------|
| 投票連結 | 短鏈或可直接記憶的 URL（如 `vote.example.org/r1`） |
| 移動端 | 投票頁面移動端優先，適配 iOS / Android 瀏覽器 + 微信內建瀏覽器 |
| 降級 | 資料庫不可用時，投票寫入 Redis 佇列緩衝，恢復後自動補寫 |
| 監控 | 投票視窗內每 30 秒健康檢查（API、Redis、PG） |

### 4.4 資料量

| 項 | 估算 |
|----|------|
| 投票人 | ~300 人 |
| 投票記錄 | ~300 條（第一輪）+ ~10 條（第二輪） |
| 輪詢請求 | 300 人 × 每 2s 一次 = 150 QPS（結果查詢） |
| 資料量 | < 10MB |

## 5. 業務規則

### 5.1 第一輪（分區選舉）

- 會員按**所屬分區**（東/南/西/北/中，共 5 區）各自投票，**每區獨立選舉**
- 每區候選人 5-7 人（後台按區配置），每區會員只看到本區候選人
- 每區每人可投 1-2 票（預設 2 票，後台可按區配置）
- **每區**得票最高者當選本區會長（副會長同區選舉產生，具體職位組合待確認）
- **平票處理**（最高票多人並列）：
  - **規則 A（預設，已要求支援）**：**平票再投** — 進入加賽輪次，僅該分區的平票候選人重新投票，得票最高者當選
    - 加賽細節（投票人範圍、票數、加賽次數上限）待討論，系統需預留加賽輪次能力
  - **規則 B（備選）**：由會務組抽籤決定
  - 具體規則由管理員在投票前確定
- 五區第一輪結束後，後台鎖定資料，管理員手動觸發第二輪

### 5.2 第二輪（總會副會長選舉）

- 參與者：第一輪當選的各區會長 + 會務幹部（小範圍，通常 3-5 人）
- 候選人：會長指定的副會長候選人（後台配置，通常 2-4 人）
- 每人投 1 票
- 得票最高者當選副會長
- 平票處理同第一輪
- 第二輪結束後，後台鎖定資料

### 5.3 幹部指派（分區級）

- 祕書、財務、總務等崗位由**各區當選會長**指派本區幹部
- 不走投票系統，系統僅記錄任命結果（後台手動錄入，按分區）
- 後台記錄各分區幹部任命資訊（姓名、崗位、所屬分區、任期）

### 5.4 任期

- 會長任期 2 年一任
- 建議承擔 2 任（最多 4 年）
- 系統在候選人資訊中顯示「當前已任屆數」，後台可配置

## 6. 投票流程（端到端）

### 第一輪：分區選舉（五區並行）

```
[管理員] 配置五個分區（東/南/西/北/中）
    ↓
[管理員] 匯入會員名單（Excel/CSV：卡號、姓名、所屬分區；卡號唯一）
    ↓
[管理員] 按分區配置候選人（每區 5-7 人，彼此不同）
    ↓
[管理員] 配置投票參數（票數、時間視窗）
    ↓
[管理員] 生成統一投票連結 + 二維碼（五區共用），可供現場展示
    ↓
[投票人] 微信掃碼 / 輸入線上投票地址（同一入口）
    ↓
[投票人] 輸入姓名 + 佛光會員卡號 + （可選）代理投票 checkbox
    ↓
[系統] 校驗卡號 + 姓名匹配（簡繁歸一化）
       ├─ 不匹配 → 報錯「未找到該會員卡號」/「姓名與卡號不匹配」
       ├─ 已投過 → 顯示「您已投過票」
       └─ 匹配 → 顯示投票人資訊（姓名、卡號、所屬分區、是否代投）
    ↓
[投票人] 點選「開始投票」→ 進入本分區候選人頁
    ↓
[投票人] 選擇 1-2 名本分區候選人 → 確認投票
    ↓
[系統] 校驗（本分區未投票、票數合法、在投票視窗內）
    ↓
[系統] 寫入投票記錄（PG，標記分區 + 是否代投）+ 更新 Redis 分區計數
    ↓
[系統] 返回「投票成功」
    ↓
[所有投票人 + 後臺] 每 2s 輪詢本分區結果，看到票數變化
    ↓
[管理員] 投票結束，確認計票完成
    ↓
[系統] 鎖定五區第一輪，顯示各區結果（每區最高票 = 本區會長/副會長）
    ↓
[若某區平票] 觸發平票再投（加賽輪次，細節待討論）
```

### 第二輪：總會副會長選舉

```
[管理員] 配置第二輪候選人（副會長候選人 2-4 人）
    ↓
[管理員] 配置第二輪參數（1 票、投票人 = 各區會長 + 幹部）
    ↓
[管理員] 生成第二輪投票連結（獨立連結）
    ↓
[各區會長 + 幹部] 通過第二輪連結投票
    ↓
[管理員] 投票結束，確認計票完成
    ↓
[系統] 鎖定第二輪，顯示結果（最高票 = 副會長）
```

### 幹部指派（分區級）

```
[各區會長] 指派本區祕書、財務、總務等
    ↓
[管理員] 後台手動錄入各分區任命資訊
    ↓
[系統] 展示完整選舉結果（各區會長/副會長 + 各區幹部名單 + 總會副會長）
```

## 7. 邊界情況

| 場景 | 處理 |
|------|------|
| 輸入的會員卡號不在名單中 | 提示「未找到該會員卡號，請核實」，不進入投票 |
| 卡號存在但姓名不匹配（含簡繁差異外的錯別字） | 提示「姓名與會員卡號不匹配，請核實」，不進入投票 |
| 姓名以簡體輸入（卡號正確） | 簡繁歸一化後匹配成功，正常進入（顯示繁體存檔姓名） |
| 投票視窗內資料庫宕機 | 投票寫入 Redis 佇列（LPUSH），消費者恢復後批次寫 PG；前端提示「投票已提交，正在處理」 |
| 投票視窗內 Redis 宕機 | 降級為直接寫 PG（效能下降但可用）；防重檢查降級為 PG 查詢 |
| 同一卡號先掃碼後直接 URL | 卡號 + 分區唯一，第二次用同一卡號時檢測到已投票，顯示「您已投過票」 |
| 同一會員卡號投到非所屬分區 | 系統依卡號判定唯一所屬分區，只能在本分區投票；跨區投票被拒（卡號綁定分區） |
| 投票視窗結束後還有人提交 | 返回「投票已結束」，不寫入 |
| 某分區平票（最高票多人並列） | 觸發該分區平票再投（加賽輪次），或按後台配置的處理規則 |
| 管理員誤操作刪除候選人（投票已開始） | 投票開始後該分區候選人列表鎖定，不允許刪除/修改 |
| 投票人投了 0 票（全部不選） | 若配置最少票數為 1，前端禁止提交；若配置最少 0 票，允許提交空票（視為棄票） |
| 網路中斷後重試 | 前端提交後顯示「正在提交...」，超時後允許重試；後端冪等（同一 token + 同一輪次 + 同一分區只接受一次） |
| 第二輪投票人非指定人員 | 第二輪連結有訪問控制（僅指定卡號可投票），非指定卡號提示「您無許可權參與本輪投票」 |
| 匯入會員名單時卡號重複 | 預檢階段報錯並列出衝突行，不寫入衝突記錄 |
| 代理投票（勾選 checkbox） | 票記錄標記 proxy=true，正常計票；後台明細可追溯代投票 |

## 8. 資料字典

### 8.1 核心實體

| 實體 | 欄位 | 說明 |
|------|------|------|
| **division**（分區） | id, name（東/南/西/北/中）, color, min_votes, max_votes, created_at | 五個分區配置 |
| **member**（會員） | id, member_no（唯一）, name_trad, name_simp, division_id, phone（選填）, created_at | 會員名單（後台匯入，member_no 唯一，綁定分區，姓名簡繁雙存） |
| **candidate**（候選人） | id, division_id, name, avatar_url, position, description, slogan, sort_order, term_count | 候選人資訊（**綁定分區**） |
| **round**（投票輪次） | id, title, status, min_votes, max_votes, anonymous, allowed_member_nos, start_time, end_time, is_runoff, parent_round_id, created_at | 輪次配置（allowed_member_nos：第二輪白名單，null=不限；is_runoff：是否加賽輪次；parent_round_id：加賽來源輪次） |
| **vote**（投票記錄） | id, round_id, member_id, division_id, candidate_ids[], proxy, proxy_voter_name, voted_at, status | 投票記錄（不可修改；round + member_id 唯一；proxy 標記代投） |
| **vote_result**（計票結果） | round_id, division_id, candidate_id, vote_count, updated_at | 快取層，Redis 為主，PG 備份（分區級） |
| **admin**（管理員） | id, username, password_hash, created_at | 管理員 |
| **appointment**（幹部任命） | id, division_id, name, position, appointed_by, appointed_at, term | 幹部任命記錄（分區級） |

> **簡繁雙存**：`member.name_trad`（繁體，匯入源值）+ `member.name_simp`（簡體，匯入時由 OpenCC 自動生成）。身份確認查詢時對輸入姓名做簡繁歸一化後與兩者之一比較，確保簡體輸入也能匹配。

### 8.2 狀態機

```
round.status:
  draft → active → closed → locked
  （草稿）  （進行中）  （已結束）  （已鎖定，不可再修改）
  加賽輪次（is_runoff=true）沿用同一狀態機，parent_round_id 指向來源輪次

member 狀態（per round + division）:
  not_voted → voted
  （未投票）  （已投票）
```

- [ ] 投票視窗外無法投票

- [ ] 結果頁面每 2 秒自動重新整理（本分區結果）
- [ ] 投票後 5 秒內本分區結果頁面可見更新
- [ ] 顯示本分區每位候選人得票數 + 柱狀圖
- [ ] 顯示本分區投票進度（已投/總人數）

- [ ] 管理員登入/登出

- [ ] 同一卡號在同一分區不可重複投票
- [ ] 卡號綁定唯一分區，無法跨區投票

- [ ] 投票記錄不可修改/刪除

- [ ] 資料庫宕機時投票不丟（Redis 佇列緩衝）
